# 本地转写（离线备用链路）

默认走腾讯会议转写。这条留作**离线 / 隐私场景**的备胎，
或者你想做到「赛后几分钟自动出图」时用。

```bash
pip install -e ".[asr]"
```

## 三条路，实测结论

### 路线 A：腾讯会议录制 + 转写（默认，推荐）

* 录制：能自动（设置里勾「自动录制」「自动文字转写」）
* **导转写稿：不能自动**。腾讯会议不落地本地转写文件，客户端也没有可读接口。
  官方唯一途径是服务端 API `GET /v1/asr/details`，
  但需要开放平台账号 + 企业管理员建应用，**个人号开不了**。

结论：导出必须手动，除非上企业账号。

### 路线 B：腾讯会议 UI 自动化

代码保留在 `wemeet_auto.py`（Win32 点击驱动，已验证可绕过 Windows 前台锁）。

**但这没有价值**：占用整台电脑、人在场才能处理遮挡/弹窗/改版、
某步错位就静默失败。UI 自动化如果还是占着电脑、还是要人看着，
那就等于手动点击，只是把它包装得更复杂。

结论：**不作为流水线的一环**，只在你想省几次点击时用。

### 路线 C：本地环回采集 + 本地 ASR（真正无人值守）

WASAPI 环回抓系统声音，本地模型转写，不依赖任何外部服务。

实测（i5-13500H，无独显，CPU int8）：

| 模型 | 架构 | RTF | 1.5h 直播耗时 | 术语准确率 |
|---|---|---|---|---|
| whisper tiny | 自回归 | 0.03 | 3 分钟 | 差（真桃→真讨、曹操→操操） |
| whisper base | 自回归 | 0.24 | 22 分钟 | 一般 |
| whisper small | 自回归 | 0.74 | 66 分钟 | 好（与腾讯会议持平） |
| **SenseVoice-small** | **非自回归** | ≈0.1 | 几分钟 | 中文专精 |

whisper 是自回归模型：每输出一个 token 都要一次前向，30 秒音频要跑几百次。
SenseVoice 是非自回归：整段音频一次前向出结果，且中文专门优化、自带标点，
正好适合赛事解说这种长段口播。

## 用法

```bash
# 1. 看看有哪些回环设备
sgs-zhanbao-local devices

# 2a. 先录后转（CPU 占用集中在赛后，看直播时不卡）
sgs-zhanbao-local record --out match.wav
sgs-zhanbao-local transcribe --wav match.wav

# 2b. 流式（边录边转，直播一结束稿子就在手里）
sgs-zhanbao-local stream

# 2c. 一条命令到底
sgs-zhanbao-local auto --score "第一场：A队 14 : 10 B队"
```

产出的 txt 直接喂给主流程：

```bash
sgs-zhanbao run --transcript voice2text/xxx-段落版.txt
```

## 模型下载

模型目录用 `SGS_ASR_MODELS` 指定，默认 `./models`。

**SenseVoice**（sherpa-onnx 官方包，含 `model.int8.onnx` + `tokens.txt`）：

```bash
curl -L -o sensevoice.tar.bz2 \
  https://github.com/k2-fsa/sherpa-onnx/releases/download/asr-models/sherpa-onnx-sense-voice-zh-en-ja-ko-yue-2024-07-17.tar.bz2
tar -xjf sensevoice.tar.bz2 -C models/
```

**流式 Paraformer**（`encoder.int8.onnx` / `decoder.int8.onnx` / `tokens.txt`）：

```bash
curl -L -o paraformer.tar.bz2 \
  https://github.com/k2-fsa/sherpa-onnx/releases/download/asr-models/sherpa-onnx-streaming-paraformer-bilingual-zh-en.tar.bz2
tar -xjf paraformer.tar.bz2 -C models/
```

**标点模型**（流式转写不带标点，配一个）：

```bash
curl -L -o punct.tar.bz2 \
  https://github.com/k2-fsa/sherpa-onnx/releases/download/punctuation-models/sherpa-onnx-punct-ct-transformer-zh-en-vocab272727-2024-04-12.tar.bz2
tar -xjf punct.tar.bz2 -C models/
```

> 模型文件都在 `.gitignore` 里，不会进仓库。

## 坑（实测踩过的）

1. **不要用 `soundcard` 0.4.x**：它默认 MediaFoundation 后端，**没有 WASAPI loopback**。
   抓系统声音必须用 `PyAudioWPatch`（portaudio + WASAPI 补丁），它能枚举 `[Loopback]` 设备。
2. **faster-whisper 国内下载不稳**：`huggingface_hub` 经常 ConnectTimeout / xet 401。
   最稳的方案是 `curl` 直连拉文件到 `models/models--Systran--faster-whisper-{size}/snapshots/main/`。
3. **重采样**：loopback 设备固定 48kHz，模型要 16k。
   `record._resample()` 用 `np.interp` 线性重采样，够用且不引入 librosa/soxr。
4. **录了半小时发现是静音**：`record` 结束时会检查峰值，低于 0.001 会警告。
   看到警告先查系统输出设备和 loopback 选错了没有。
5. **流式模型不提供精确时间戳**：只有「已喂入多少音频」的估算，
   所以流式产物的时间戳是近似值。校对步骤不依赖时间戳也能跑（走全片段替换）。

## 结论

本地转写**能跑，但只有 small 以上可用**，代价是赛后等 1 小时（whisper small）。
SenseVoice 快一个数量级，是这条链路唯一能做到「赛后几分钟出图」的方案。
默认还是走腾讯会议——音质好、术语准、不用占 CPU。
