# 自动化边界：哪些能自动，哪些不能

这份文档记录**实测结论**，不是推测。要改方案前先看这里，避免重复踩坑。

## 需求本质

一场直播（1.5 小时）→ 一张战报长图。要无人值守，就要回答一个问题：

> **转写稿从哪来？**

这是唯一绕不开的环节。战报生成和出图已经全自动了。

## 能自动的 ✅

| 事 | 状态 | 实现 |
|---|---|---|
| 校对 → 提取 → 出图 | ✅ 全自动 | `sgs-zhanbao run` |
| B站直播间状态检测 / 轮询开播 | ✅ | `bilibili.py` |
| 系统声音录制 | ✅ | `record.py`（WASAPI 环回） |
| 本地离线转写 | ✅ | `asr.py` / `stream_asr.py` |
| 腾讯会议窗口唤起、按钮点击 | ⚠ 技术可行 | `wemeet.py`（AttachThreadInput 绕前台锁） |

## 不能自动的 ❌

**腾讯会议转写稿的导出。**

转写内容只存在云端，客户端没有可直接读取的本地文件。
官方只有服务端 API（`GET /v1/asr/details`），需要腾讯会议开放平台账号 +
企业管理员建应用，**个人号拿不到**。

## 为什么放弃了 UI 自动化

技术上能做（窗口定位、绕过前台锁、坐标换算都验证过），但**没有价值**：

* 它占用整台电脑，你不能同时做别的事
* 人在场才能处理被遮挡、最小化、弹窗、客户端改版
* 纯像素点击一旦某步错位就**静默失败**，无人值守反而更危险

> UI 自动化如果还是占着电脑、还是要人看着，那就等于手动点击，
> 只是把它包装得更复杂。

代码保留在 `wemeet_auto.py`，只在你想省几次点击时用，不作为流水线的一环。
它默认 dry-run，加 `--go` 才真点，且每步之后截图存档便于回溯。

## 推荐的用法：半自动

每天实际只需要动 2 下：

1. 打开 B站直播间 → 腾讯会议「快速会议」→「共享屏幕」→「仅电脑声音」
2. 会后从腾讯会议导出逐字稿，丢进 `voice2text/`
3. 剩下的全自动：`sgs-zhanbao run` → 出图

比全自动方案更稳，也不会半夜悄无声息地失败。

## 想要真·无人值守

走本地转写那条路（`sgs-zhanbao-local auto`），代价是模型下载 + CPU 时间。
详见 [本地转写.md](本地转写.md)。

## 时间预算（半自动路线）

| 步骤 | 耗时 |
|---|---|
| 开直播间 + 建会议 + 共享 | 2 分钟 |
| 直播时长 | 约 1.5 小时 |
| 导出逐字稿 | 1 分钟 |
| AI 校对（逐段找错 + 终审） | 约 2-3 分钟 |
| AI 提取（分块摘要 + 生成） | 约 2 分钟 |
| 渲染出图 | 约 15 秒 |
| 人工复核修正清单 | 3-5 分钟 |

**赛后到拿到成品，约 6-8 分钟。**
