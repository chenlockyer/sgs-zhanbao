# 版式与素材

## 三段式版式：上下固定、只拉伸正文

| 素材 | 尺寸 | 作用 |
|---|---|---|
| `head.png` | 928×830 | 固定头部（装饰带 + 面板上沿花角 + 记者牌 + 标题底衬） |
| `mid.png` | 928×239 | 纵向拉伸填充正文（`background-size: 100% 100%`） |
| `tail.png` | 928×556 | 固定尾部（云海 + 收口线，底部信息区压在上面） |

设计稿宽度 **928**，出图用 `device_scale_factor=2`，成品 **1856px** 宽。
所有坐标常量都在 `render.py` 顶部：

```python
W = 928
TEXT_L, TEXT_R = 96, 84      # 正文左右边距
TITLE_TOP = 782              # 标题压在头图空白带上的 y
BYLINE_CX, BYLINE_CY = 464, 674   # 记者牌中心
TAIL_BOTTOM = 104            # 底部信息区离页面底边
FS_TITLE, FS_BODY = 48, 32   # 字号
```

## 配色：Palette 是唯一来源

CSS 里出现的每一个颜色都来自 `config.Palette`，不再写死在字符串里。

```python
from sgs_zhanbao.config import Config, Palette
from sgs_zhanbao.render import render_report

cfg = Config(palette=Palette(
    headline="#2C6B52",     # 主标题、比分数字
    deep="#2C6B52",        # 小标题、队名、正文强调
    byline="#3E8E6E",      # 记者署名
    dot="#9FD4BC",         # 圆点、表格描边、虚线框
    paper="#F3FAF6",       # 页底色
))
render_report(report, output_path="out.png", cfg=cfg)
```

只改一两个色时用环境变量更省事，不用写代码：

```bash
set SGS_COLOR_HEADLINE=#2C6B52
set SGS_COLOR_DEEP=#2C6B52
set SGS_COLOR_PAPER=#F3FAF6
```

字段名大写即可：`SGS_COLOR_<字段名>`。全部字段：
`headline / deep / byline / body / paper / dot / row_even / row_border /
card_bg / bottom_sec / bottom_tomorrow`。

> **历史坑**：原先 `config.py` 里有个 `Theme` dataclass，docstring 写着
> 「改这里就能换皮」，但 `render.py` 的 CSS 从没读过它 —— 改了静默无效，
> 颜色全在 CSS 字符串里写死。表现就是「换了素材配色，文字还是玫红」。
> 现在 `Theme` 已删除，`Palette` 是唯一的配色入口，
> 并且 `tests/test_config.py::TestPalette::test_every_field_reaches_css`
> 会逐个字段验证它真的进了 CSS —— 加一个没人读的颜色字段，测试直接红。

改 `paper` 时记得同步改素材（`scripts/build_art.py`），否则接缝处颜色对不上。

## 中部条怎么做的（关键，决定成败）

正文区要从 239px 拉到上万 px（约 40 倍）。任何「逐列」的细微差异都会被放大成竖条纹。
所以中部条必须满足三条约束：

1. **列内纵向恒定** → 拉伸后绝无竖条纹
2. **首行逐像素 == 头部末行** → 头部接缝 0 色差
3. **末行逐像素 == 尾部首行** → 尾部接缝 0 色差

`build_art.py` 的做法：取中部源图的**逐列中位数**当剖面（去掉纸面细纹理），
整条 mid 就是这个剖面重复 239 次；head 末段 / tail 首段各 48 行向剖面渐变。

三件套的约束由 `tests/test_build_art.py` 守着。
会校验接缝差值和列内 std，不达标直接 fail。

## 接缝为什么必须严丝合缝

`.body` 底边就是尾图顶边。只要中间漏出 1px，露出来的是页面底色 `#FCEFEE`，
而且这条缝会**横贯整幅**、把左右花框的竖线截断——看上去就是一条横线。

典型成因：正文最后一段的 `margin-bottom` 塌陷出了 `.body`
（单场比赛时 `_fit_bottom_card` 算出的 `padding-bottom` 正好是 0，堵不住塌陷）。

两道保险：

```css
.body { display: flow-root; }   /* 建立 BFC，挡住 margin 塌陷 */
```

```python
_fix_seam(page)   # 实测「头→正文」「正文→尾」两处间距
                  # 有缝就补 padding-bottom / margin-top
                  # 补不齐直接抛错中止出图，不让带缝的图流出去
```

## 底部信息区：绝对定位压在尾图上

看点总结 / 明日预告 / 恭喜语是 `.bottom-card`，绝对定位压在尾图上，
垫一层 30% 白的「中间实、四周渐隐」柔边（CSS mask）让字更清楚。

它的字号和正文一样大，所以**比尾图还高**。渲染前按实测高度给正文补白：

```
信息区顶端 - 正文末行 = padding_bottom + 尾高 - TAIL_BOTTOM - 信息区高

要这个间距 == CARD_GAP，于是
padding_bottom = CARD_GAP + TAIL_BOTTOM + 信息区高 - 尾高
```

所以正文写多写少都不会压字——版式自适应。

## 标题压在素材上

主标题是绝对定位（`.headline`，`top: TITLE_TOP`）直接放在头部素材底部那条
空白带上的——**素材不裁切**，做法和底部信息区压尾图完全一致。

早先版本踩过两个坑，都别再来一次：

* 把正文区向上盖住头图 → 切掉边框、出现分界线
* 直接裁头图 → 浪费素材

## 字体

正文用楷体，按「本张图实际用到的字」做子集、base64 内嵌，**不走系统字体渲染**：

```python
FONT_PATH  # 显式指定 > SGS_FONT > 系统楷体 > None
```

查找顺序（`config.find_system_kaiti()`）：

```
Windows:  C:\Windows\Fonts\simkai.ttf → STKAITI.TTF
macOS:    ~/Library/Fonts/STKaiti.ttf
Linux:    /usr/share/fonts/**/AR PL UKai CN.ttf → LXGWKaiTi.ttf
```

找不到就退回浏览器默认字体（能出图，观感变差）。

> 仓库里**不含任何字体文件**：Windows 楷体、方正隶变的授权都不允许随代码分发。
> 商用请自行确认所用字体的授权范围，见 [NOTICE](../NOTICE)。

正文样式：32px、加粗、行距 1.15、字距 -0.045em，左右边距 96/84；主标题 48px 不缩。

## 换素材

```bash
# 方式一：用自己的三张源图重建（928 宽的 头部.png / 中部可复用部分.png / 尾部.png）
python scripts/build_art.py --src <源图目录> --dst <输出目录>

# 方式二：不动包，运行时指过去
set SGS_ART=D:\我的素材        # 目录里放 head.png / mid.png / tail.png
```

源图宽度必须是 928，否则 `build_art.py` 会拒绝（版式坐标是按 928 写死的）。

## 篇幅约定

`extract_report.md` 固定写：焦点局 2 条、名场面 1 条（各 80 字内）、看点 5 行（各 30 字内）。
条目数是结构要求，不是字数限制——正文不限字数，版式自适应。

**看不懂的不写**：转写稿是同音误听重灾区（武将/技能/选手/队名/环节名）。
提示词铁律要求——凡无法确认对应真实存在的名词、或拼出来读者会问「这是什么东东」的，
一律略去或改用不带专有名词的平实描述；宁可少写一个细节，也不要写生造词；
存疑词只进 `meta.notes`，正文不出现。
